## 用同一份資料比較新舊主題

[開啟或另存單檔練習頁](/examples/alarm-priority/demo.html)，不需安裝套件。這與[警報優先級練習](/articles/hmi-alarm-priority-display-rules)共用五筆固定合成資料；本篇只驗證換色的影響，不再另造一套警報生命週期。

按「14:03:00」、選「全部五筆」，先保持原版 theme/v1。預期順序是 Q2、Q1、Q4、Q3、M1。Q2 顯示 High、作用中／已確認、已逾期30秒；Q3 是條件已消失／未確認。已確認不等於已消失，換色不能改變這兩個欄位。

這是瀏覽器離線顯示案例，不連 PLC，也沒有 Ack、Reset、通知擱置或自動控制。原版與候選版都是教材色票，不代表任何廠牌或 IEC 的規定。

## 六步重現換色與回退

| 操作                          | 應看到的結果                                     | 若不一致，先查哪裡             |
| ----------------------------- | ------------------------------------------------ | ------------------------------ |
| 1. 按14:03:00、全部五筆、原版 | Q2逾期30秒，Q1剩餘120秒                          | 虛擬時間與篩選是否相同         |
| 2. 選候選 theme/v2            | 左側色條變色；五筆順序與所有文字不變             | 主題切換是否意外修改資料或排序 |
| 3. 勾黑白顯示                 | 仍能讀出Q2已確認且作用中、Q3已消失且未確認       | 是否只剩色彩表示狀態           |
| 4. 選只看未確認               | 4／5筆；Q2被篩選排除，不是被清除                 | 篩選範圍與計數                 |
| 5. 回全部、改回原版、取消黑白 | 五筆恢復顯示，原版色條回來；Q2仍已確認且作用中   | 回退是否誤重設狀態             |
| 6. 選候選版，開瀏覽器列印預覽 | 保留theme/v2版本文字、範圍、五筆狀態；控制列隱藏 | 列印CSS是否遺失版本或狀態      |

列印樣式把色條改為黑色，仍保留文字。瀏覽器可能依使用者設定省略背景色，所以不要以列印出的色票確認警報狀態。本文自動檢查的是 print 媒體樣式，不是實體印表機輸出。

## 哪些東西改了，哪些不應被改

兩版只改卡片左側裝飾色條，文字與白色背景保持相同。對照表是實際CSS值：

| 本例的顯示分組 | theme/v1 | theme/v2 | 不可由色條取代的資訊                |
| -------------- | -------- | -------- | ----------------------------------- |
| 預設           | #315c78  | #553c7b  | High／Low、作用中／已消失、確認狀態 |
| 作用中且到期   | #a32424  | #8a4200  | 已逾期秒數，不自動升級              |
| Low提醒        | #54654c  | #365d60  | Low文字與具體工作說明               |

這不是「紅色=Active、綠色=Clear」的狀態映射；同一色條可能包含多種確認狀態，必須讀文字。擱置原因與期限由[TimedShelve案例](/articles/alarm-suppression-shelving-outofservice)處理，本頁沒有假裝實作該欄位。

## 軟體檢查與人員驗收分開

本文在 Edge 自動核對三種寬度（320、768、1440px）：換色與回退前後清單文字不變、候選版篩選正確、黑白資訊保留、列印樣式保留版本，以及原有期限與鍵盤流程。這能抓到程式改壞資料的問題，不能證明熟悉舊畫面的操作員能同樣快速辨識新版。

下載[人員任務紀錄表](/examples/alarm-priority/migration-tasks.csv)。每列的 status 都是 not_run，時間與實際回答留空，不能當作已完成的使用者測試。用同一位受測者、相同虛擬時間與篩選，分別記錄原版與候選版；主持人不要提示顏色。請受測者回答「哪筆已確認卻仍作用中」「哪筆已消失但未確認」「哪筆沒有期限」，記下實際答案、完成秒數與誤判原因。

若候選版出現誤判，保留資料快照與版本，先修文字或排列再重測；不要只因程式測試通過就發布。現場字體放大、環境光、遠距離、讀屏及真實操作員測試尚未執行。

[W3C 使用顏色說明](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)要求資訊不能只靠色彩傳達。[文字對比說明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)另規範一般文字的最低對比；黑白切換不是對比量測，也不是完整無障礙認證。若正式改版連文字、背景或焦點色都改，必須另外測那些實際配對，不能沿用本例只換色條的結果。
