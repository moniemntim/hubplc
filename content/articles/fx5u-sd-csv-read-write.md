## 將 PLC 數值寫成可閱讀的紀錄

本篇介紹 FX5U 如何用 SP.FWRITE 把數值轉成 CSV 檔案，再用 SP.FREAD 把 CSV 數值讀回 PLC。CSV 用逗號分隔欄位、用換行區分紀錄，適合用文字編輯器或試算表查看。

先讀懂原始寫入程式，再看官方讀取範例。兩者的檔名、欄數與要求筆數不同；接著再用本篇的對照表，學會讓讀取設定匹配寫入結果。

| 教材項目       | 對應內容                                                  |
| -------------- | --------------------------------------------------------- |
| PLC 與工具     | FX5U，GX Works3，梯形圖 ProgPou                           |
| 原始寫入專案   | csv檔寫入20250107.gx3，共 100 步                          |
| 名為讀取的專案 | 教材標為 csv檔讀取20250107.gx3 的截圖，實際顯示 SP.FWRITE |
| CSV 讀取補充   | 三菱官方 SP.FREAD 的 sample.csv 範例，清楚標示官方參考圖  |
| 原寫入檔名     | "1"，CSV 模式自動補成 1.CSV                               |

檔名不是判斷程式用途的依據：請查看實際使用 SP.FWRITE 還是 SP.FREAD。本文不將「csv檔讀取」中的寫入畫面當成讀取範例。

本文依《SD卡 CSV檔案讀寫教學》整理，並核對文末所列的三菱官方指令手冊。教材截圖保留原介面與註解；內文使用繁體中文。藍色區塊是離線編輯器選取範圍，不代表接點正在導通。點選圖片可開啟原尺寸查看指令。

## 1 CSV 的列欄與資料型態

例如一列文字 100,200,300 代表三個欄位，不是三個字元。CSV 的檔案大小會隨數字位數、負號、逗號及換行而變動，因此寫入 16 字數值，不代表 CSV 檔案只有 32 bytes。

| 原始設定        | 形成的資料                                                     |
| --------------- | -------------------------------------------------------------- |
| D0=H100         | CSV 十進位帶符號 16 位數值寫入，數值解讀範圍為 -32768～32767。 |
| D7=K0           | 來源以字為單位；此專案每掃描重設 D7。                          |
| D100=K16        | 本次轉換並寫出 D101～D116，共 16 個數值欄位。                  |
| D6=K0           | 不指定分欄數，本次資料寫成單列，即 16 欄一列。                 |
| D4:D5=FFFFFFFFH | 寫到檔案尾端。                                                 |
| D3=H0           | 保留正常追加方式；與檔尾設定搭配時，新增下一列。               |

原始資料前 7 欄來自 TRD：年、月、日、時、分、秒、星期。後 9 欄 D108～D116 在原梯形圖未被賦值，會把當時的裝置內容一起寫出；要做新手練習，應先填入明確的辨識值。

使用文字編輯器確認原始 CSV 再用試算表開啟。試算表可能自動轉換日期、長數字或前導零；畫面看似相同，不代表存回後的文字仍符合 PLC 格式。數值讀取練習不要加入標題列、公式或千分位逗號。

## 2 操作準備與控制資料表

準備適用的 FX5U、SD 卡、GX Works3 與讀卡機，先備份專案和卡上檔案。請在獨立教學設備確認 CPU 型號與卡片格式；依硬體手冊停止卡片存取後再取卡。

| 裝置       | 原 CSV 寫入設定與用途                       |
| ---------- | ------------------------------------------- |
| D0         | H100：十進位帶符號 16 位轉 CSV              |
| D1         | 初始 H0；指令完成後回報狀態碼               |
| D2         | 初始 K0；指令完成後回報實際寫入數           |
| D3         | H0：正常追加，不把最後換行改成逗號          |
| D4、D5     | DMOV H0FFFFFFFF D4；32 位元內容為 FFFFFFFFH |
| D6         | K0：本次 16 個數值寫成一列                  |
| D7         | K0：字單位，SM400 每掃描重設                |
| D100       | K16：要求寫入 16 字                         |
| D101～D107 | TRD 寫入年、月、日、時、分、秒、星期        |
| D108～D116 | 另 9 字，練習前須明確指定內容               |

D4:D5 是兩字組成的檔案位置，不可只看低字 D4。原指令顯示 H0FFFFFFFF，前導 0 不改變這個 32 位元全 1 的值；以有號十進位監看時會看到 -1。

本篇指令表採 GX Works3 梯形圖的操作數順序。若改用 ST，參數排列必須重新對照 ST 語法，不能直接照抄梯形圖文字順序。

## 3 CSV 寫入程式 初始化

<a href="/images/fx5u-sd-csv-read-write/image1.png"><img src="/images/fx5u-sd-csv-read-write/image1.png" alt="圖 1  CSV 寫入原始專案第 1～4 列" width="1195" height="473" loading="lazy"></a>

圖 1 CSV 寫入原始專案第 1～4 列

SM402 在 RUN 後第一次掃描把 D0 設為 H100，選擇 CSV 十進位帶符號 16 位模式；D1、D2、D3 清為 0。副檔名只是外觀，真正決定轉換方式的是 D0。

D2 為完成後的實際寫入數，不是要求數量。要求寫出多少個數值，要看後面的 D100。每次執行完成應同時核對 D1 與 D2。

## 4 CSV 寫入程式 追加與單列設定

<a href="/images/fx5u-sd-csv-read-write/image2.png"><img src="/images/fx5u-sd-csv-read-write/image2.png" alt="圖 2  CSV 寫入原始專案第 5～8 列" width="1195" height="462" loading="lazy"></a>

圖 2 CSV 寫入原始專案第 5～8 列

DMOV 將 D4:D5 設為 FFFFFFFFH，選擇檔尾追加；D3=0 表示正常新增下一列。D6=0 代表本次資料只形成一列，不是「沒有資料欄位」。

D100=16 表示來源為 D101～D116。D7 在 SM400 下每掃描設為 0。若把 D4:D5 改成其他值，CSV 寫入會改走從開頭重寫的行為，原檔內容會被清除後重建，不能當成任意列的插入位置。

## 5 CSV 寫入程式 M1 與檔案指令

<a href="/images/fx5u-sd-csv-read-write/image3.png"><img src="/images/fx5u-sd-csv-read-write/image3.png" alt="圖 3  CSV 寫入原始專案第 9～12 列，步號 40 與 52 起" width="1195" height="473" loading="lazy"></a>

圖 3 CSV 寫入原始專案第 9～12 列，步號 40 與 52 起

原 M1 上升沿且 SM753=OFF 時，執行 RST M0、RST M100、SET M101。這是取消／重置用的實際邏輯，不能把它當成一次寫入啟動。M3 週期段才會 SET M0。

M0=ON 且 SM606=OFF 時，執行 SP.FWRITE U1 K2 D0 "1" D100 M100。K2 指 SD 卡；"1" 自動成為 1.CSV。完成位是 M100，異常完成位是其下一點 M101。

## 6 CSV 寫入程式 保存完成結果

<a href="/images/fx5u-sd-csv-read-write/image4.png"><img src="/images/fx5u-sd-csv-read-write/image4.png" alt="圖 4  CSV 寫入原始專案第 12～15 列，包含完成處理" width="1195" height="473" loading="lazy"></a>

圖 4 CSV 寫入原始專案第 12～15 列，包含完成處理

正常完成時 M100=ON、M101=OFF，原程式 SET M150；異常完成時 M100、M101 一起 ON，SET M151。完成分支同時 RST M0，結束這一次執行保持。

M150、M151 沒有自動清除，可能保留不同次的結果。練習前先清除兩位，完成後再核對 D1=0、D2=16。卡片空間不足可能只寫入部分資料，不能只看檔案存在。

## 7 CSV 程式末段 時鐘與每秒觸發

<a href="/images/fx5u-sd-csv-read-write/image5.png"><img src="/images/fx5u-sd-csv-read-write/image5.png" alt="圖 5  名為 CSV 讀取的原檔之實際末段；與 CSV 寫入檔內容相同" width="1260" height="489" loading="lazy"></a>

圖 5 名為 CSV 讀取的原檔之實際末段；與 CSV 寫入檔內容相同

SM400 讓 TRD D101 持續更新七個時鐘欄位。M3=ON 時，SM412 的每次上升沿 SET M0，下一掃描由前段 FWRITE 執行。CSV 已使用檔尾追加，所以這裡沒有 BIN 範例的 DADDP 位置遞增。

M3 週期分支沒有串接 SM753；資料來源又每掃描刷新。開始先做單次測試，正式記錄功能再加入忙碌互鎖與資料快照，確保一次存取完成前不變更正在使用的內容。

## 8 實作一 建立並檢查 CSV 紀錄

先建立一筆可以讀懂的資料，再測試新增第二列。下列操作在教學設備執行，原始 GX Works3 檔案不修改。

1. 先讓 M3、M1、M0 為 OFF，確認 SM753=OFF、SM606=OFF，並備份既有 1.CSV。

1. 確認 RUN 初始化完成，D0=H100、D3=0、D4:D5=FFFFFFFFH、D6=0、D7=0、D100=16。清除 M150、M151。

1. 將 D108～D116 設為 108～116。D101～D107 由 TRD 提供，不要在這七字設定固定值期待保留。

1. 將 M0 設為 ON 一次，等待本次完成，確認 D1=0、D2=16、M0 已解除，並記錄結果。單次練習不使用 M1，也不開啟 M3。

1. 再做一次同樣的單次觸發。如果原檔已存在，兩次操作應增加兩列，不是取代前一列。

1. 依 CPU 手冊完成停止卡片存取後，使用讀卡機與文字編輯器檢查 1.CSV。每列應有 16 個數值欄位；前七欄為保存時的時鐘，後九欄應為 108～116。

一列的示意內容如下，這只是格式示例，實際日期與時間由 CPU 決定：

```csv
2026,9,8,14,30,5,2,108,109,110,111,112,113,114,115,116
```

不要用「16 字 = 32 bytes」判斷 CSV 大小。數字轉成文字後，還包含逗號、可能的負號及換行；應改用欄數與數值內容檢查。

## 11 官方讀取流程與練習結果

官方啟動條件是 X0 上升沿，並檢查 SM753=OFF。啟動時 SET M0，RST M100、M101；M0 與 SM606 常閉條件成立後執行 SP.FREAD。完成時依 M101 區分正常與異常，保存到 M150 或 M151，最後 RST M0。

在獨立測試檔 sample.csv 中準備以下五列，每列五個數值。這份練習檔只用數值，不加入欄位標題。

| 列  | 第 1 欄 | 第 2 欄 | 第 3 欄 | 第 4 欄 | 第 5 欄 |
| --- | ------- | ------- | ------- | ------- | ------- |
| 1   | 101     | 102     | 103     | 104     | 105     |
| 2   | 201     | 202     | 203     | 204     | 205     |
| 3   | 301     | 302     | 303     | 304     | 305     |
| 4   | 401     | 402     | 403     | 404     | 405     |
| 5   | 501     | 502     | 503     | 504     | 505     |

1. 在教學副本依官方讀取範例準備程式與控制資料，確認 CPU 型號、檔名與接點用途。原始名為 CSV 讀取的檔案不可直接當作這個讀取程式。

1. 先清除 M150、M151 舊結果，確認沒有其他檔案存取，給 X0 一次受控上升沿。

1. 完成後檢查 D1=0、D100=20。D101～D105 應為 201～205，D106～D110 為 301～305。

1. D111～D115 應為 401～405，D116～D120 為 501～505。第 1 列 101～105 不應出現在此次結果。

以上是可供實作驗證的預期結果，不是已執行的硬體測試。若 D100 不足 20，先核對剩餘列數、欄數及檔案內容；若某欄成為 0，還要檢查是否轉換失敗。

## 12 如何讀回原程式寫出的 1.CSV

官方範例用 5 欄一列、共讀 20 個數值；原寫入專案卻是 16 欄一列。要讀回原檔，必須把檔名、資料數、列位置及欄數一起對齊。下表是教學用讀取設定，不是原 csv檔讀取 專案的現有內容。

| 讀取項目   | 匹配原寫入格式的設定                        |
| ---------- | ------------------------------------------- |
| 指令       | SP.FREAD U1 K2 D0 "1.CSV" D100 M100         |
| D0         | H100：CSV 十進位 16 位                      |
| D1、D3     | 初始化為 0；D1 完成後由系統更新             |
| D2         | K16：讀一筆 16 欄的紀錄                     |
| D4、D5     | 0：從檔案開頭；或指定第 n 列來讀某筆紀錄    |
| D6         | K16：以原寫入的 16 欄為一列                 |
| D7         | K0：本例使用字單位                          |
| D100       | 完成後應為實際讀入的數量，完整一列為 16     |
| D101～D116 | 前七字為時鐘，後九字為練習時指定的 108～116 |

若 D6 設為 0，SP.FREAD 會忽略換行，將資料當成連續數值讀取；這不代表自動只讀一列。為了讓初學者清楚辨識原本的紀錄邊界，本練習明確使用 D6=16。

FREAD 的 FFFFFFFFH 表示從上次讀取結束位置接續，不是「讀最後一列」。接續讀取必須維持同一檔案及相容的格式設定；第一次練習應使用明確列號，較容易核對結果。

## 13 CSV 問題排查與改良方向

| 現象                     | 判斷方式                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------- |
| 開啟讀取檔卻一直新增資料 | 先看實際指令。教材中名為 csv檔讀取 的畫面仍是 SP.FWRITE，不能當成讀取程式。            |
| 只寫第一列或舊資料消失   | 確認 D4:D5 是否仍為 FFFFFFFFH。CSV 非檔尾設定會重寫原檔。                              |
| 新資料接在最後一列後面   | 檢查 D3.b0；設 1 會把最後換行轉成逗號接續最後一列，本範例使用 0。                      |
| 每列欄位數不是預期       | FWRITE 的 D6=0 是本次資料只寫一列；原要求 16 字，所以每列 16 欄。                      |
| D100=16 但讀回不是 16 欄 | 讀取要求數應設在 D2；D100 是系統回報。再核對欄數、列號及是否為初始化舊值。             |
| 某些欄位讀入後變成 0     | 可能包含標題、無法轉換字元或超出範圍的數值。這些欄位仍可能計入實際數量，必須核對內容。 |
| M150、M151 都亮          | 兩位保留舊結果，練習前清除，再依本次完成與 D1、實際數量判斷。                          |
| 資料時間不一致或漏筆     | TRD 每掃描刷新，M3 又沒有忙碌互鎖。正式記錄應先複製資料快照，等存取完成後才送下一筆。  |

若要改成 BIN32、無符號數、ASCII 或浮點數，不只是改副檔名。需一併核對 D0、D7、資料區大小與允許範圍；本篇先固定使用原範例的 16 位數值，避免混用。

連續記錄的驗收應包含檔案大小、每列欄數、紀錄總數、時間順序與錯誤情境。卡片未就緒、空間不足及部分寫入都應保留狀態碼與實際完成數量。

## 14 檢核與參考資料

- 能說明 CSV 的欄位數、資料數與檔案 bytes 為何不同。

- 能指出原程式的檔尾追加設定，以及更改該設定可能造成的重寫行為。

- 能在原始截圖辨認 M1 重置、M3 週期啟動與完成結果保存。
