## 先開啟可操作範例

[開啟警報優先級練習](/examples/alarm-priority/demo.html)。也可把這個 HTML 另存成 `demo.html`，用瀏覽器開啟；它不需要安裝套件或連線服務。本文在 Windows 的 Edge 實際核對三種寬度及鍵盤操作。

頁面是五筆合成資料的固定快照。拖動時間只改反應倒數，沒有連線設備，也不會送出 Ack、Reset 或改寫警報。此處的 High／Low 與反應時間都是教材設定；不能把它當成現場警報合理化或安全允許時間。

## 核對兩筆同級警報

Q1在14:00:00發生，教材設定300秒反應時間，到期14:05:00。Q2在14:00:30發生，反應時間120秒，到期14:02:30。兩者都是High，Q2雖較晚發生，期限更近所以排在Q1前。

| 操作         | Q2應顯示               | Q1應顯示  | 是否改變優先級   |
| ------------ | ---------------------- | --------- | ---------------- |
| 按14:01:00   | 剩餘90秒               | 剩餘240秒 | 否，兩筆都High   |
| 按14:03:00   | 已逾期30秒（仍為High） | 剩餘120秒 | 否               |
| 拖到14:02:30 | 已逾期0秒              | 剩餘150秒 | 否，等號視為到期 |

計算式是 `deadline = started + response`、`remaining = deadline − now`。本頁用「14點後的整數秒數」作同一虛擬時鐘，不混入來源設備時間。只有作用中的列才顯示反應倒數；條件已消失的列顯示「反應倒數不適用」，不代表已完成工作結案。

## 不只靠顏色辨識

先勾選「黑白顯示」，再找Q2。它仍寫著「High」「作用中／已確認」與剩餘或逾期秒數；失去顏色後資訊不能消失。Q3則是「條件已消失／未確認」，應保留待確認狀態。這兩個例子可以排除「已確認就是已修好」的錯誤呈現。

Q4故意沒有反應期限，文字是「未設定」，不能用0秒代替；M1是本班安排的Low保養提示。這只是對照資料，不代表所有保養提醒都應納入操作警報。現場若沒有明確可執行動作，應先檢討它究竟是警報、事件還是工作提醒。

用Tab移到時間按鈕後按Enter，或聚焦滑桿後按方向鍵，也應能改變虛擬時間。畫面有文字、位置與狀態欄，不需要辨認紅綠才知道哪筆未確認。[WCAG 2.2「使用顏色」說明](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)支持資訊不能只以顏色傳達；本頁的黑白與鍵盤檢查不是完整無障礙符合性認證，也沒有真人色覺測試。

## 篩選後一定要看範圍

依序執行：

1. 選「全部五筆」，初始順序為Q2、Q1、Q4、Q3、M1。
2. 選「只看未確認」，顯示4／5筆，Q2因已確認而被此篩選排除；它仍是作用中，沒有被刪除。
3. 選「只看作用中」，顯示4／5筆，Q3因條件已消失而不在此視圖。
4. 回到全部，五筆都應再次可見。

每次篩選上方都顯示檢視名稱與筆數，避免把目前四筆誤當全部狀態。本例不保存個人篩選設定；重新開檔會回到預設。

## 本例排序規則

規則版本為 `display-priority/v1`，比較順序是：

1. High先於Low。
2. 同級先列作用中且已逾期，再列作用中未到期，再列作用中但期限未設定，最後列條件已消失。
3. 同組比較到期時間、發生時間，最後用固定ID決勝。

逾期只增加文字與秒數，不自行升成Critical。這個操作期限排序與[嚴重度／可信來源時間排序](/articles/alarm-severity-time-stable-order)是兩種明訂的清單政策，不能混用鍵值後仍說是同一規則。前者幫人看反應期限，後者重建固定事件快照；都不直接證明設備風險高低。

## 從練習移到現場前要補哪些資料

為每個警報逐項填入：後果、可執行動作、反應時間的依據、優先級核准版本，以及確認成功或條件恢復的證據。範例的300秒和120秒不能直接複製到設備。不要從「安全門」「泵浦」等名稱自動推導最高級，也不要用HMI倒數取代獨立保護功能。

本文實際檢查了320、768、1440px三種寬度、期限與等號、篩選、黑白文字、鍵盤及頁面錯誤。未驗證特定HMI元件、告警聲音、現場光線或操作人員反應時間。需要管理確認與人工結案時，接著閱讀[警報工作流案例](/articles/hmi-alarm-ack-clear-reset-workflow)；需要保留大量原始事件與摘要時，閱讀[洪水摘要案例](/articles/hmi-alarm-flood-event-summary-followup)。
