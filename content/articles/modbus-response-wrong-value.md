## 先界定：工具能算什麼，不能驗證什麼

本篇用[Modbus 位址換算](/tool/modbus-address/)和[暫存器與 Float32 轉換](/tool/register-converter/)重現資料判讀。兩者都在瀏覽器內計算：**不會連線、送出 Modbus 請求、讀取 PLC／從站或驗證任何實體設備。**以下結果是軟體換算與模擬案例，沒有進行實體 PLC、從站、線路或現場數值驗證。

開始前，先保存一筆可追溯的讀取紀錄：設備資料表版本、站號、資料區、功能碼、手冊中的位址寫法、讀取數量、完整原始回覆、時間、設備面板的已知值，以及倍率／偏移／無效碼定義。只看 HMI 顯示的最後數字，無法分辨讀錯位址、型別或倍率。

本篇只處理「已有可保存的回覆，但數值解讀不對」。逾時、RTU CRC 錯誤、TCP 訊息格式錯誤或例外回覆，先依通訊診斷程序處理；不要藉由改倍率掩蓋它們。

## 案例一：40010 到底該送哪個位址

假設設備資料表明確把目標列為 Holding Register 的傳統五位參考編號 `40010`。在「Modbus 位址換算」逐欄輸入：

| 工具欄位 | 要選或填入的值 |
| --- | --- |
| 資料區 | `Holding Register (4x)` |
| 參考編號位數 | `五位數` |
| 輸入種類 | `參考編號` |
| 參考編號 | `40010` |

結果列必須是：

| 結果列 | 預期結果 |
| --- | --- |
| 參考編號 | `40010` |
| 零起算位址 | `9` |
| 從 1 起算序號 | `10` |
| HEX 位址 | `0009` |
| 讀取功能碼 | `03` |

這個案例的封包起始位址是 `0009`，不是十進位 `40010`。工具的功能碼來自所選資料區；它沒有確認你的設備是否真的把該列定義成 Holding Register。若資料表寫的是 `Address 9` 或 `0009H`，先確認它本來就是零起算位址，再在「輸入種類」選 `零起算位址` 並填 `9`，不要再減一。

### 第二組交叉檢查：Input Register 的六位參考編號

把欄位改為下列值：

| 工具欄位 | 要選或填入的值 |
| --- | --- |
| 資料區 | `Input Register (3x)` |
| 參考編號位數 | `六位數` |
| 輸入種類 | `零起算位址` |
| 零起算位址 | `100` |

預期結果為參考編號 `300101`、零起算位址 `100`、從 1 起算序號 `101`、HEX 位址 `0064`、讀取功能碼 `04`。這可用來抓出把 Input Register 當 Holding Register，或把五位與六位表示法混在一起的錯誤。

## 案例二：原始字組正確，為何還是顯示錯值

假設已保存的兩個暫存器為 `4148 0000`，而資料表指定 IEEE 754 Float32、位元組排列 ABCD。開啟「暫存器與 Float32 轉換」，依序設定：

| 工具欄位 | 要選或填入的值 |
| --- | --- |
| 方向 | `暫存器 → 數值` |
| 資料型別 | `Float32 (IEEE 754)` |
| 位元組排列 | `ABCD` |
| 暫存器 HEX（以空白分隔） | `4148 0000` |

結果列「數值」應為 `12.5`。這個數字只有在資料表明定該型別和 ABCD 排列時才可解讀為工程量；它本身沒有單位，也沒有證明設備目前值是 12.5。

反向驗算可排除手抄字組錯誤：將「方向」改成 `數值 → 暫存器`，保留 Float32、ABCD，在「數值」填 `12.5`，結果列「暫存器 HEX」應為 `4148 0000`。

### 用一次只改一項的方式檢查排列

如果保存的順序是 `0000 4148`，不要直接把它當 ABCD 的 `12.5`。先保持「資料型別」為 Float32，只把「位元組排列」改為 `CDAB`，並在「暫存器 HEX（以空白分隔）」填 `0000 4148`；結果才應為 `12.5`。這表示本案例資料的兩個 word 順序與 ABCD 相反。

不要同時改「位元組排列」、型別與倍率。每次只改一項，再用另一筆已知且不同的資料重複驗證；否則錯誤設定有時會巧合地產生一個看起來合理的數字。

## 案例三：16 位元有號值與倍率要分兩步

假設資料表寫明一個暫存器是 Int16，工程倍率是 `0.1 °C/count`，保存值為 `FFF6`。在「暫存器與 Float32 轉換」填：

| 工具欄位 | 要選或填入的值 |
| --- | --- |
| 方向 | `暫存器 → 數值` |
| 資料型別 | `Int16` |
| 暫存器 HEX（以空白分隔） | `FFF6` |

結果「數值」應為 `-10`。再依資料表的倍率在工具外明確計算：`-10 × 0.1 = -1.0 °C`。倍率不是暫存器工具的輸入欄位；若先把 `FFF6` 當 UInt16，或忘了乘 `0.1`，得到的數字都會錯。

建議資料流程保留四個可追溯欄位：原始 HEX、資料型別／位元組排列、解碼後數值、工程倍率與偏移後的值。再加上本次讀取時間與品質狀態，才不會把「上一次有效值」誤認成剛讀到的新值。

## 失敗案例與對應處置

| 觀察到的畫面或結果 | 可重現的輸入 | 先做的處置 |
| --- | --- | --- |
| 位址工具拒絕第一筆前的參考編號 | Holding Register、五位數、參考編號 `40000` | 工具會顯示位址範圍錯誤；確認資料表是否採 4xxxx 參考編號，勿盲目減一。 |
| Float32 少一個 word | Float32、`暫存器 → 數值`、`4148` | 工具會顯示「請輸入 2 個四位 HEX 暫存器。」先取得完整兩個 16 位元暫存器。 |
| 兩個 word 顛倒後出現極小或極大值 | ABCD、`0000 4148` | 保留原始字組，依資料表逐一測試 ABCD、BADC、CDAB、DCBA；不要把異常值直接截斷。 |
| 值恰為 `65535` 或看似不合理 | UInt16／Int16 都可能產生不同解讀 | 查資料表的型別與無效碼；工具無法推斷設備廠商定義。 |
| 值恰好多／少 10 倍 | 已解碼值加上資料表倍率 | 核對倍率是否已在設備或 HMI 套用，避免重複乘除。 |

「讀到回覆」不是「讀到正確資料」。如果回覆的功能碼、資料長度、站號或例外狀態不符合原始請求，先回到通訊紀錄；不要把它帶入轉換工具當成一般暫存器數值。

## 完成判定與現場界線

以下三件事同時成立，才完成本篇的**軟體判讀**練習：

1. `40010` 可重現為 offset `9`、HEX `0009`、FC `03`。
2. `4148 0000` 以 Float32／ABCD 可重現為 `12.5`，且反算能回到同一字組。
3. `FFF6` 以 Int16 可重現為 `-10`，依已知倍率換成 `-1.0 °C`。

實體設備驗證仍需在不寫入設備的前提下，依現場程序比對至少兩筆不同且已知的狀態、原始回覆、設備面板與工程值，並確認通訊中斷時資料會被標為過期或失效。這些現場動作不在本篇或網站工具的執行範圍內。
