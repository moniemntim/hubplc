## 這篇交付什麼

如果規格書只寫「支援 Modbus TCP」，不能據此填入「支援 Modbus Security」。本篇提供兩張可填寫的表，讓你在挑選設備或安排測試前，找出缺少哪份文件、哪一段仍未受保護。

- [能力盤點 CSV](/examples/modbus-security/capabilities.csv)：型號、韌體、文件頁碼、文件聲明與觀察結果分欄。
- [分層測試計畫 CSV](/examples/modbus-security/test-plan.csv)：七項測試的前提、輸入、預期、實際及證據位置。

目前能力欄全部是 `unknown`，測試欄全部是 `not_run`，沒有填入任何設備通過紀錄。本篇是導入盤點與驗收準備，不是特定 PLC 的設定教學，也沒有 TLS 實機或模擬器測試結果。

## 先畫出 TLS 在哪裡結束

Modbus Security 官方規格將 mbap 放入 TLS，使用系統埠 802；傳統 Modbus TCP 使用 502。Security 的雙向認證與角色授權是不同能力；若提供角色授權，角色到權限的對照取決於產品設計。以上核對 [Modbus/TCP Security 規格第 5、8.2、8.4 節](https://www.modbus.org/file/secure/modbussecurityprotocol.pdf)。

下面是**自訂拓樸示例**，不是現場網路圖：

```text
用戶端 —— TLS/802 —— 閘道 —— 明文 Modbus TCP/502 —— PLC
                      ↑ TLS 在此結束
```

在這張圖中，應分別盤點用戶端、閘道及 PLC。即使第一段成功建立 TLS，也不能把 PLC 那一列的 `native_mbaps` 填成已證實。第二段是否准許存在、誰可連入、是否隔離，是另一項網路設計決定。VPN 也需要標出端點；加上一條 VPN 連線不會改變 PLC 本身的協定能力。

## 開啟能力表，按這個順序填

1. 每個產品各複製一份表。填入完整型號與韌體版次，不只寫「Q 系列」或「閘道器」。
2. 找該版本的通訊／資安手冊，把頁碼或章節放在 `document_reference`。行銷頁只寫 TLS，不足以填寫原生 mbaps 的支援結論。
3. 在 `documented_value` 寫文件實際提供的能力：例如可用的服務、雙向憑證、角色對照、載入後是否需重啟。文件沒有寫的項目保留 unknown，列入供應商問題單。
4. `observed_value` 只寫測試時取得的結果，附測試表 case_id。尚未執行時保持空白；文件聲明不搬過來充當觀察結果。
5. 盤點憑證續期、撤銷、時鐘與回復方法。這些資料會決定能否安排隔離測試，以及憑證失效時誰能恢復服務。

例如手冊只列「Modbus TCP server、502」，可在 `documented_value` 記錄原文位置；`native_mbaps` 的狀態仍是 unknown，不能把「沒有查到」直接當成所有版本皆不支援。若供應商明確表示該型號／韌體不支援，才記錄這個具體範圍的否定結論。

## 七項測試不要混成一個連線成功

CSV 中的預期是測試計畫，並非已觀察的結果。先補齊能力表與隔離環境，再按照產品實際管理介面執行。

| 測試 | 主要要觀察什麼 | 不足以判定的訊號 |
| --- | --- | --- |
| S01 合法憑證 | 雙方認證與本次使用的憑證指紋 | 802 的 TCP 連接成功 |
| S02 合法讀取 | 指定讀取範圍的回應與已知預期值 | TLS 握手成功 |
| S03 錯信任根 | 新握手被拒，保留兩端錯誤紀錄 | 應用畫面顯示離線 |
| S04 過期憑證 | 使用隔離測試憑證的新握手被拒 | 既有長連線仍可讀取 |
| S05 不允許的角色 | 該請求被拒，測試目標未被修改 | 只看到憑證有效 |
| S06 禁止明文回退 | 802 不可用時，沒有政策禁止的 502 替代連線 | 只看到第一次 802 失敗 |
| S07 續期 | 新完整握手使用新指紋，讀取通過，回復程序可用 | 檔案已上傳或管理畫面已刷新 |

規格 §8.4 的 R-16 對角色授權使用 SHOULD，R-17 才規定提供此能力時必須遵守該節要求。S05 僅在確認產品提供且啟用角色授權後執行；未提供時，可附產品文件與範圍核准依據標 not_applicable。能力未知仍是 unknown／not_run，不能逕自填不適用。若本站點架構強制要求角色授權，產品未提供就表示本地需求未滿足，不能因 S05 不適用而判整體通過。

S05 必須先取得產品的角色對照與可控測試目標，不能對運轉設備隨便發寫入請求。規格 §8.4 的授權拒絕使用例外 01；但例外 01 也可能表示不支援功能，需配合授權紀錄判讀，不能單憑回覆碼確定原因。

S06 是本表選定的安全架構要求；若系統刻意保留 502，需另列允許的路徑及控制方式，不能把 502 的成功當成 Security 測試成功。S07 要依產品方法結束舊會話並驗證新的完整握手，否則可能仍在使用既有連線或恢復會話。

## 交接時，讓下一個人知道缺哪一步

每個實測列至少填時間、兩端型號／版本、實際連接埠、憑證指紋、結果與證據位置。私鑰不放入這份表或公開附件。狀態用 pass、fail、not_run、blocked，或有明確依據的 not_applicable；「測不了」要寫缺少的設備、文件或環境，不能改成 pass。

當握手成功但 S02 失敗，往 Modbus 請求與設備資料表查；S01 就失敗時，先查信任鏈、有效期、時鐘及產品的端點身分核對規則。這樣交接才能指向下一個動作，而不是只留「TLS 不通」。
