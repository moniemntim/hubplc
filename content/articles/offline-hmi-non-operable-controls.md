離線時可以保留 52.0 °C 供人查看，但「看得到」不代表它仍可用來決定寫入。本篇用一個能直接開啟的 HTML，將本地快取、線上查詢與寫入分成三個按鈕，讓你逐項核對，而不是只把連線燈改成紅色。

**本例是合成資料與瀏覽器介面測試，不連接 PLC、HMI 或後端。** 按下「模擬寫入」只改本頁的計數與文字，沒有命令送出。真正的命令重連、世代與 unknown 處理請接著看 [HMI 重連完整事件案例](/articles/hmi-reconnect-stale-callback-unknown-write)，此處只處理操作員看見什麼、能按什麼。

## 先打開示範，不必安裝套件

開啟 [離線畫面示範 demo.html](/examples/offline-hmi/demo.html)。也可以將該檔另存到新資料夾，再用 Edge 或 Chrome 開啟；CSS 與 JavaScript 都在同一檔內，不需要其他檔案或網路資源。

1. 保持「線上：教材條件全部通過」。畫面應顯示 52.0 °C、Good、本機收件經過 1000 ms、世代 13／13；三個按鈕都可用。
2. 按「模擬寫入（僅本頁）」。下方應出現「本機示範接受 1 次；沒有送出設備命令。」再按一次才變 2 次。
3. 切換「離線：只能查看快取」。數值仍是 52.0 °C，但查詢和寫入禁用；原因明列「離線，無法提交」與「本機收件經過已達 5000 ms」。
4. 用 Tab 移到「查看本地快取」，按 Enter。應展開固定歷史 `50.0 → 51.0 → 52.0 °C`，文字明說沒有重新讀設備。離線仍可讀這份既有資料。
5. 再依下表切換其他情境。每次切換都清除示範寫入計數；它不是持久化的命令紀錄。

## 十個固定情境的核對表

三個按鈕的分工是：本地查看讀取已存在的合成歷史；線上查詢按鈕只示範「目前允許查詢」的提示；寫入按鈕只有在本篇全部教材條件通過時才開放。這個小例子假設讀取權限存在，寫入權限另外判斷。

| 情境                 | 顯示值／本機收件經過 | 查詢 | 模擬寫入 | 必須讀得到的原因                  |
| -------------------- | -------------------- | ---- | -------- | --------------------------------- |
| 線上條件全通過       | 52.0 °C／1000 ms     | 可   | 可       | 教材條件通過，不代表設備接受      |
| 離線                 | 52.0 °C／11000 ms    | 禁止 | 禁止     | 離線、收件經過超過上限            |
| 重連同步中           | 52.0 °C／1000 ms     | 禁止 | 禁止     | 同步中、快照世代 12 不等於現行 13 |
| 收件經過剛好 5000 ms | 52.0 °C／5000 ms     | 可   | 禁止     | 已達本例時限                      |
| 品質 Uncertain       | 52.0 °C／1000 ms     | 可   | 禁止     | 來源品質不是 Good                 |
| 沒有寫入權限         | 52.0 °C／1000 ms     | 可   | 禁止     | 沒有有效寫入權限                  |
| 前一筆命令 unknown   | 52.0 °C／1000 ms     | 可   | 禁止     | 先釐清前一筆結果                  |
| 時鐘識別不一致       | 52.0 °C／未知        | 可   | 禁止     | 不能算收件經過                    |
| 來源新鮮度未確認     | 52.0 °C／1000 ms     | 可   | 禁止     | 不能因剛收到就視為新採樣          |
| 沒有有效快照         | —／未知              | 可   | 禁止     | 不以零補值，沒有現行世代的快照    |

「查看本地快取」在十個情境都可用，因為獨立的固定歷史資料一直存在；最後一列缺少的是本頁用於判斷的有效快照，不是聲稱歷史檔案也不存在。示範沒有替不同資料來源自動合併歷史。

## 收件經過不是設備採樣年齡

HTML 內的 `baseline` 與 `cases` 是全部輸入。預設 `nowMs=2000`、`receivedMs=1000`，兩者 clock ID 相同，因此本機收件經過為 1000 ms。`nowMs` 和 `receivedMs` 都是固定的教材單調時間，不是瀏覽器正在量測的時鐘；頁面放十分鐘也不會自動增加。

本例的寫入條件要求收件經過 **小於 5000 ms**，4999 可通過、5000 即拒絕。5000 是教材門檻，不是通用 PLC 或 HMI 標準。不同 clock ID、缺時間或時間倒退都顯示未知，不能補成 0 ms。

就算本機剛收件，也可能收到來源快取。因此另有 `sourceFreshConfirmed`，表示外層已依設備契約核對來源新鮮度的**假設輸入**。範例不會讀設備時間、同步時鐘或證明該條件真的成立；「來源新鮮度未確認」情境故意把它設為 false。正式系統須定義來源身分、品質、採樣或版本規則，再決定這個條件，不能只看 TCP 已連線。

Good 也不是永遠有效的通行證。離線情境仍保留上次資料的 Good，但連線狀態與收件經過已禁止寫入；讀者必須同時看旁邊的文字原因，不能單看一個 Good 標籤。

## 如何改成自己的驗收表

先列出每個元件是本地查看、線上查詢，還是會改變控制狀態的命令。把各自的禁用條件與操作員可見原因寫在同一列；不要用一個全域 enabled 同時決定三者。

用文字編輯器開啟 HTML，可以找到 `decide(input)`。它會逐項收集原因，再決定是否開放本頁示範。你可以把 baseline 的 nowMs 改成 5999 或 6000，保持 receivedMs=1000，重載頁面對照 4999／5000 ms 邊界；不要只把按鈕的 disabled 屬性刪掉，就當成條件通過。

本頁事件處理器在按鈕被觸發時還會重新判斷本地條件，但**這仍然不是後端授權**。使用者可以修改下載的整份程式；正式服務必須自行驗證使用者權限、設備狀態、版本與命令結果，PLC 的互鎖與安全停機也不依賴這個網頁。此教材不提供實際啟停元件或離線自動排程。

unknown 的命令處理不在這裡重新發明。畫面只說明為何暫停新命令；查詢不到或查詢逾時，都不能直接改成未執行。重連示範中的 operationId、狀態查詢與放開再按政策，見前述連結。

## 本機已核對的範圍

單檔另存後，已用本機 Edge 在 320、768、1440 px 對照十個情境，共 30 組。另核對鍵盤展開快取、4999／5000 邊界，以及改掉 disabled 後，事件處理器仍拒絕不合本地條件的示範操作。測試過程沒有 HTTP 資源請求。

介面使用可見文字解釋原因、原生 disabled 按鈕、label 與描述關聯，避免只靠灰色表達狀態。這不等於完成整份 WCAG 或所有讀屏器驗證；採用文字而不只靠顏色的理由可參考 [W3C：Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。

若你的畫面離線後變成 0，先查是否把「缺值」轉成數字；若仍顯示舊值卻能寫入，查每項禁用條件；若只亮紅燈而說不清原因，先補元件旁的說明，再測操作流程。
