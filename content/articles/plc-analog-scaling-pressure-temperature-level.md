## 這是瀏覽器試算案例，不是現場 PLC 驗收

本篇的每一步都可在瀏覽器重現，目的是先把量程、比例與結果判讀講清楚。工具只在瀏覽器內計算：它**不會讀取 PLC、感測器或 HMI，也沒有對任何實體設備做配線、校正或功能驗證**。把數字用於現場前，仍須以該類比模組、感測器與製程的手冊和核准程序驗收。

先準備這些資料，再開始輸入：

| 必要資料 | 這個案例使用的值 | 現場要從哪裡確認 |
| --- | --- | --- |
| 訊號型式與端點 | 4–20 mA | 感測器銘牌／資料表與通道設定 |
| 工程量與單位 | 0–10 bar | 感測器量程和 HMI 顯示規格 |
| 原始計數端點 | 0–4000 counts | **特定**類比模組的設定與手冊 |
| 原始監看值 | 2000 counts | PLC 監看畫面或已保存的測試紀錄 |

`0–4000` 只是本案例設定，並非任何 PLC、CPU 或通訊模組的通用規格。若 PLC 已把資料換成 bar、°C 或 m，就不要再把工程值當原始 counts 縮放一次。

## 案例一：12 mA 為什麼是 5 bar

開啟[類比訊號換算](/tool/analog/)，依下表逐欄設定。欄名與工具畫面完全相同；選「常用訊號」後，工具會自動帶入訊號端點與單位，仍可確認其值。

| 工具欄位 | 要選或填入的值 |
| --- | --- |
| 常用訊號 | `4–20 mA` |
| 輸入種類 | `訊號值` |
| 訊號值 | `12` |
| 訊號單位 | `mA` |
| 訊號下限 | `4` |
| 訊號上限 | `20` |
| 工程下限 | `0` |
| 工程上限 | `10` |
| 轉換到其他訊號 | `0–10 V` |

結果列應顯示：

| 結果列 | 預期結果 |
| --- | --- |
| 訊號值 | `12 mA` |
| 工程值 | `5` |
| 百分比 | `50 %` |
| 目標訊號 | `5 V` |

計算式是 `比例 = (12 − 4) ÷ (20 − 4) = 0.5`，所以 `工程值 = 0 + 0.5 × (10 − 0) = 5 bar`。工具的「工程值」結果本身沒有單位欄位；本案例依輸入量程把它判讀為 `5 bar`，不要把數字 5 自動當成所有現場都是 bar。

### 用端點和中點找出量程填錯

保持其他欄位不變，只改「訊號值」。這三次輸入是同一條直線的最小驗算組。

| 訊號值 | 預期工程值 | 預期百分比 | 判讀 |
| --- | --- | --- | --- |
| `4` mA | `0` | `0 %` | 低點對上工程下限 |
| `12` mA | `5` | `50 %` | 中點對上量程中點 |
| `20` mA | `10` | `100 %` | 高點對上工程上限 |

若三點都固定高 1 bar，優先核對「工程下限」或顯示端是否另加偏移。低點正確、越往高點越偏，優先核對「工程上限」、訊號端點，或是否把 0–20 mA 當成 4–20 mA。這些是軟體計算上的定位線索，不能代替量測訊號或校驗器驗證。

## 案例二：把同一條比例換成溫度與液位

仍在「類比訊號換算」，保留 `4–20 mA` 和「訊號值」`12`，只改工程端點。結果以每一列對應的工程單位解讀。

| 工程下限 | 工程上限 | 工具的工程值 | 本案例判讀 |
| --- | --- | --- | --- |
| `-50` | `150` | `50` | `50 °C` |
| `0` | `6` | `3` | `3 m` |
| `0` | `10` | `5` | `5 bar` |

若要反算感測器應送出的電流，改「輸入種類」為 `工程值`，填入 `5`，並設定工程下限 `0`、工程上限 `10`。結果列的「訊號值」應為 `12 mA`、「百分比」為 `50 %`。這只能確認線性公式的正反算一致；它不代表感測器真的已輸出 12 mA。

## 案例三：PLC 顯示 2000 counts 時怎麼換算

類比工具的「訊號值」欄位是 mA 或 V，不能把 `2000` counts 填進去。已取得特定模組的原始端點後，改用[PLC 原始值縮放](/tool/plc-scaling/)：

| 工具欄位 | 要選或填入的值 |
| --- | --- |
| 方向 | `原始值 → 工程值` |
| 原始值預設 | `自訂` |
| 原始值 | `2000` |
| 原始下限 | `0` |
| 原始上限 | `4000` |
| 工程下限 | `0` |
| 工程上限 | `10` |

結果應為「工程值」`5`、「百分比」`50 %`、「狀態」`範圍內`；按本案例量程即 `5 bar`。把「原始值」改為 `0`、`1000`、`3000`、`4000` 時，工程值依序應為 `0`、`2.5`、`7.5`、`10`。

原始值與訊號電流是否真的是 `0 ↔ 4 mA`、`4000 ↔ 20 mA`，取決於模組配置。若通道配置是 0–20 mA，而感測器實際為 4–20 mA，不能沿用本表的原始低點；先由該模組設定找出 4 mA 與 20 mA 各自對應的 counts，再填「原始下限」與「原始上限」。

## 邊界與失敗案例：結果看起來正常前先看狀態

### 超出訊號端點時，工具會外推而不截斷

回到「類比訊號換算」，維持 4–20 mA、0–10 的設定，將「訊號值」填 `3.2`。結果會是工程值 `-0.5`、百分比 `-5 %`，並出現「超出量程：結果為線性外推值。」這不是工具替你判定斷線，也不是有效的壓力讀值；它只表示數學比例落在量程外。

現場應依感測器、模組與安全程序定義低於 4 mA 的處置。不要為了讓畫面好看而直接截成 0 bar，否則可能把異常偽裝成真實低壓。

### 上下限相同或反向，工具會拒絕計算

把「訊號下限」填 `20`、把「訊號上限」填 `4`，或把工程上下限填成相同值，工具會顯示「上限必須大於下限。」原因是分母為零或方向不成立。此時修正量程來源，不要用倍率硬湊出一個數字。

### 小數消失不是量程正確的證據

本案例的原始值 `1000` 必須得到 `2.5`，不是 `2`。若 PLC 或 HMI 顯示為整數，檢查縮放程式是否先做整數除法、運算中間值是否溢位，以及 HMI 是否把小數位隱藏。保留「原始值、工程值、品質／有效狀態」三個欄位，才能區分數學結果與資料是否可信。

## 現場採用前的最終檢核

1. 先以已保存、已知的訊號或原始值，在瀏覽器重跑端點與中點，確認公式和資料表一致。
2. 現場再依設備手冊與核准程序，用適當量測或校驗方式，比對訊號、PLC 原始值與 HMI 工程值；本篇沒有執行這一步。
3. 對每一個超量程、斷線或資料失效情況，確認 PLC／HMI 顯示品質狀態，而不只看數值是否被限制在量程內。
