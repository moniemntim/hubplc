## 這一課要做出什麼

做一個內部運轉位元 FanReq：Start 按下一次後保持 1，Stop=1 時立即在該次掃描清成 0。Start 和 Stop 同時為 1，停止優先。上方模型可直接操作，下面給出相同邏輯的梯形圖結構與 ST 對照。

**驗證範圍：**本站瀏覽器模型可執行並記錄每次掃描；它不執行三菱或其他廠牌指令，也不代表 GX Simulator／實體 PLC 已測試。FanReq 只是內部位元，不連接馬達或 Y 輸出。

| 變數 | 型別／初值 | 用途 |
| --- | --- | --- |
| Start | BOOL／0 | 本次掃描看到的啟動請求 |
| Stop | BOOL／0 | 本次掃描看到的停止請求；1 表示要求停止 |
| FanReq | BOOL／0 | 運轉請求；每掃描讀取前值後再寫入新值 |

這裡的 Stop 是已轉換成「1=要求停止」的邏輯訊號，不是現場常閉按鈕端子的原始電位。接線常開／常閉與程式條件必須分開。

## 五次操作，看見建立、保持與停止

先按上方「全部重設」。每一列都先設定勾選狀態，再按一次「執行 1 掃描」。沒有勾選就是 0。

| 掃描 | Start | Stop | FanReq 預期 | 原因 |
| --- | --- | --- | --- | --- |
| 1 | 0 | 0 | 0 | 初始待機 |
| 2 | 1 | 0 | 1 | 啟動成立 |
| 3 | 0 | 0 | 1 | 啟動放開，由前值保持 |
| 4 | 0 | 1 | 0 | 停止切斷保持 |
| 5 | 1 | 1 | 0 | 同時命令仍停止 |

第 3 列是重點：Start 已經是 0，FanReq 仍是 1。若第 3 列變成 0，通常是沒有回授支路；若第 5 列變成 1，停止條件沒有涵蓋啟動與保持兩條路徑。

## 梯形圖與 ST 要寫的是同一條式子

梯形圖結構如下。`[/Stop]` 是對邏輯 Stop 取反；`[Start]` 與 `[FanReq]` 並聯，最後只有一個 FanReq 一般線圈。

```text
        +---[ Start ]---+
--[/Stop]              +---( FanReq )
        +---[ FanReq ]--+
```

對應布林式：`FanReq_next = NOT Stop AND (Start OR FanReq_before)`。

以下是 ST 語意對照。三個 BOOL 必須先宣告，程式每個循環執行一次；本篇沒有在特定廠牌編譯器編譯它。

```iecst
VAR
    Start  : BOOL := FALSE;
    Stop   : BOOL := FALSE;
    FanReq : BOOL := FALSE;
END_VAR

FanReq := (NOT Stop) AND (Start OR FanReq);
```

同一個 FanReq 不應另外被其他段落寫入。若 HMI、手動段與自動段都能改 FanReq，這個三變數案例就不再描述完整控制權；先搜尋所有寫入點再判讀。

## 用 SET／RESET 時，也要把優先條件寫清楚

同一個功能可以表示為：

```text
Start AND NOT Stop  → 設定 FanReq
Stop               → 清除 FanReq
```

第一條刻意排除 Stop，避免同時成立時同一位元又設又清。不同平台的指令名稱、可用裝置與重複線圈檢查不同；此處只比較邏輯，不能把這兩行文字當成 Q 系列可匯入程式。

一般線圈每次依公式決定結果；SET／RESET 沒被執行時保留狀態。兩者都不等於「斷電保持」：重啟後是否保留由裝置類別、保持區與初始化規則決定。本模型的「全部重設」固定把所有值歸零，不能用來驗證 CPU 斷電行為。

## 必須親自試的邊界：停止解除後會不會自己啟動

承接第 5 掃描，**保持 Start=1，只把 Stop 改成 0**，再掃描一次。FanReq 會變成 1。這是這條電平邏輯的預期結果，不是模型故障。

如果規格要求「停止解除後必須放開、重新按啟動」，就不能直接使用這個公式的 Start 電平。要改成新的啟動事件，並定義第一次進入 RUN 時如何處理已按住的按鈕。[下一課的狀態機](/articles/plc-state-machine-three-step-sequence)採用上升緣請求，可比較兩者。

| 症狀 | 第一個要看的欄位 | 判讀 |
| --- | --- | --- |
| 放開 Start 就停止 | 第 3 掃描的 FanReq 前值 | 回授未參與運算或位元被別處清除 |
| Stop=1 仍運轉 | 第 5 掃描 Stop 與 FanReq | 邏輯極性或停止優先條件錯誤 |
| 解除停止又啟動 | Start 是否一直為 1 | 本例電平邏輯的結果；需要重新觸發規格 |
| 實體設備仍轉動 | FanReq 之後的命令與回饋 | 本模型只到內部請求，未驗證驅動器與機械反應 |

完成這一課的標準是：能重現五列結果，並解釋為什麼解除 Stop 時仍按著 Start 會再次啟動。實機測試、急停與安全回路不在這個內部位元模型的範圍內。
