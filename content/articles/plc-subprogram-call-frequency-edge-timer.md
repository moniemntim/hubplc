條件為假而跳過功能塊呼叫時，該實例沒有取得這一掃描的輸入，也不會替你更新內部前值。這和「每掃描呼叫，但不採用 Q」不同。CODESYS 說明功能塊透過實例呼叫、每個實例各自改變；輸出與內部變數會保留到下一次執行。[Function Block 文件](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_obj_function_block.html) 也明示這些規則。R_TRIG 的公開介面是 `CLK` 與上升緣時為真的 `Q`，TON 則定義 `IN`、`PT`、`Q`、`ET`；本文不把下面的 JavaScript 模型當作任一 PLC 的執行期或標準 TON 實作。[R_TRIG 文件](https://content.helpme-codesys.com/de/libs/Standard/3.5.18.0/Trigger/R_TRIG.html) [TON 文件](https://content.helpme-codesys.com/en/libs/Standard/3.5.17.0/Timer/TON.html)

## 先下載並重播離線模型

下載 [`call-frequency-model.mjs`](/examples/plc-call-frequency/call-frequency-model.mjs) 與 [`demo.mjs`](/examples/plc-call-frequency/demo.mjs) 到**同一個資料夾**。兩個檔案以相對匯入連結，沒有套件、網路、設備或模擬器依賴；需要 Node.js `>=22.13.0`。在該資料夾執行：

```sh
node --version
node demo.mjs
```

程式固定初始狀態為 `previous=false, q=false`。一次「呼叫」先以 `clk && !previous` 算出 `q`，再把 `previous` 寫成 `clk`；一次「跳過」不改這兩個欄位。每條時間線都重新初始化，時間單位是案例的整數毫秒，不代表控制器掃描精度。

## 同一輸入，跳過呼叫和每掃描呼叫

下表的 A 只在 `called=1` 時呼叫，B 每列都呼叫。兩者從相同的初始狀態開始。100、200 ms 的 A 沒有取樣，所以 300 ms 才拿 `previous=0` 與高電位比較；B 在 100 ms 已看到第一次上升，200 ms 又看到了低電位，因此 300 ms 是另一個上升緣。

|  ms | CLK | A called | A previous 前→後 | A Q | B previous 前→後 | B Q |
| --: | --: | -------: | ---------------- | --: | ---------------- | --: |
|   0 |   0 |        1 | 0→0              |   0 | 0→0              |   0 |
| 100 |   1 |        0 | 0→0              |   0 | 0→1              |   1 |
| 200 |   0 |        0 | 0→0              |   0 | 1→0              |   0 |
| 300 |   1 |        1 | 0→1              |   1 | 0→1              |   1 |
| 400 |   1 |        1 | 1→1              |   0 | 1→1              |   0 |

這只表明各實例在自己的呼叫點怎麼判斷，不能證明輸入恰好在 300 ms 才上升。若需要停用時仍維持前值同步，採用 B：每掃描呼叫，事件採用條件寫成 `Enable AND Q`。若刻意選 A 的凍結行為，恢復時的高電位是否能形成命令必須另外寫成政策。

## Q 保留時，不要重複消費同一事件

這條線獨立初始化。100 ms 呼叫後 `Q=1`；200 ms 跳過，因此保存的 `Q` 還是 1。若下游每個掃描只看保存的 Q，會把同一事件加兩次；若只在「本次真的呼叫且 Q 為 1」時採用，總數是一次。

|  ms | CLK | called | Q 保存值 | 天真的累計（每列 Q=1 就加） | 單次採用（called AND Q） |
| --: | --: | -----: | -------: | --------------------------: | -----------------------: |
|   0 |   0 |      1 |        0 |                           0 |                        0 |
| 100 |   1 |      1 |        1 |                           1 |                        1 |
| 200 |   1 |      0 |        1 |                           2 |                        1 |
| 300 |   1 |      1 |        0 |                           2 |                        1 |

因此事件契約至少要記錄本次是否呼叫、Q 是否為真和是否已採用。不能只用畫面上仍為真的 Q 當作新事件。若接收端需要佇列或確認，請按該介面明確保存與清除事件。

## 恢復時保持高電位，和漏掉短脈衝

下面兩條線都從 `CLK=0` 開始。A 在停用期間跳過；B 一直呼叫，但 100、200 ms 的 `Enable=0` 不採用 Q。到 300 ms 恢復時，A 把持續的高電位判成事件，B 已經同步過前值，因此 Q 是 0。

|  ms | CLK | Enable | A called / Q | B Q / 採用 |
| --: | --: | -----: | ------------ | ---------- |
|   0 |   0 |      1 | 1 / 0        | 0 / 0      |
| 100 |   1 |      0 | 0 / 0        | 1 / 0      |
| 200 |   1 |      0 | 0 / 0        | 0 / 0      |
| 300 |   1 |      1 | 1 / 1        | 0 / 0      |

若恢復的高電位不應自動命令，包裝層可在第一個恢復呼叫只做 `previous=clk, q=false`，下一個連續呼叫才恢復一般邊緣判斷。這是自訂同步政策，不能說成 R_TRIG 的 Reset 介面。

另一條獨立線是 0 ms 低、100 ms 高、200 ms 又低，而 A 在 100、200 ms 都跳過：

|  ms | CLK | A called | A Q | 可由 A 還原短脈衝？ |
| --: | --: | -------: | --: | ------------------- |
|   0 |   0 |        1 |   0 | 不適用              |
| 100 |   1 |        0 |   0 | 否                  |
| 200 |   0 |        0 |   0 | 否                  |
| 300 |   0 |        1 |   0 | 否                  |

最後只有目前的低電位與舊前值，已經沒有短脈衝的資料。需要捕捉短脈衝時，要依目標 I/O、任務週期或高速捕捉功能的文件與實測決定，這個離線模型無法替代。

## 計時：明寫期限政策或缺口政策

以下是範例檔中的兩個**自訂**模型，皆不宣稱標準 TON 行為。兩者在 0 ms 開始，目標期限 300 ms；100 ms 有一次呼叫，200 ms 跳過，300 ms 再呼叫。期限模型以 `nowMs - startedAtMs >= durationMs` 判斷，所以 300 ms 得到 `expired=1`。缺口模型另要求任兩次呼叫相距不得超過 150 ms；300 ms 距離上次呼叫 200 ms，結果是 `TIME_GAP` 且不宣布到期。

|  ms | called | 絕對期限 elapsed / expired | 缺口模型 gap / error / expired |
| --: | -----: | -------------------------- | ------------------------------ |
|   0 |      1 | 0 / 0                      | 0 / — / 0                      |
| 100 |      1 | 100 / 0                    | 100 / — / 0                    |
| 200 |      0 | 100 / 0                    | 100 / — / 0                    |
| 300 |      1 | 300 / 1                    | 200 / TIME_GAP / 0             |
| 400 |      1 | 400 / 1                    | 100 / TIME_GAP / 0             |

選絕對期限代表恢復時按可信時間戳判定到期；選缺口政策代表資料不連續時先交出診斷，由上層決定重試、同步或停機。範例的 `TIME_GAP` 是黏住的：之後即使呼叫間隔變短，仍維持錯誤與 `expired=0`。要重新開始，應由上層建立新的 `initialGapTimer(...)` 狀態並記錄原因。兩種選擇都要把 `startedAtMs`、允許間隔、恢復處置與事件採用規則寫進需求。標準 TON 的 `Q`、`ET` 與未呼叫時的實際行為，仍須按使用的 CODESYS 版本、CPU 與專案任務在受控測試核對；官方 TON 文件僅定義輸入、延遲、Q 與 ET，不能拿本模型當平台驗證。

## 現場查法與驗收項目

先從呼叫點追到實例名稱，再同時記錄 `Enable`、`CLK`、本次是否呼叫、呼叫前後前值、Q、事件採用旗標、時間戳和缺口診斷。用不同實例比較 A 與 B；若改變呼叫順序就改變結果，再查是否共用同一實例、全域暫存或多處寫入。

驗收至少要覆蓋表中的五種情形：條件跳過、停用仍呼叫、Q 保留、恢復高電位、停用期間高低往返。計時另確認所選的期限或缺口政策。這些離線重播能驗證案例的狀態轉移，沒有連接 PLC、沒有讀 I/O，也沒有驗證任何廠牌的掃描週期、計時器或安全功能。涉及設備動作的輸出仍須有獨立互鎖、模式與安全設計。
