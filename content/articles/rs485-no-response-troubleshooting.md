## 先建立一條最小測試連線

先用一個主站、一個從站與短距離線路測試，停用其他輪詢來源。你要先分清楚「沒有送出」「從站沒回覆」與「有回覆但被接收端丟棄」，才知道下一步該查哪裡。

| 測試項目   | 本篇示例                    | 實機請填 |
| ---------- | --------------------------- | -------- |
| 通訊協定   | Modbus RTU                  | ＿＿＿＿ |
| 站號       | 1                           | ＿＿＿＿ |
| 通訊格式   | 9600 bps，8E1               | ＿＿＿＿ |
| 讀取方式   | 手冊允許的 FC03 唯讀資料    | ＿＿＿＿ |
| 線路方式   | 依雙方支援的 RS485 二線方式 | ＿＿＿＿ |
| 逾時與重試 | 先用有限等待，暫停連續重試  | ＿＿＿＿ |

8E1 是 8 個資料位元、偶同位、1 個停止位元。範例值只供測試記錄，從站若固定其他格式，主站就要配合。兩端都寫 RS485，也不代表它們使用相同上層通訊協定。

### 沿用 Q 系列教材時

Q06UDVCPU 搭配 QJ71C24N 時，先核對實際使用 CH2 的 RS422／485 介面、模組起始 I/O 位置，以及專案對應通道。使用預定義協定時，PLC 程式與模組的協定資料都要一致。具體設定畫面可對照既有[Q 系列 RS485 Modbus RTU 讀寫教學](/articles/q-series-rs485-modbus-rtu/)。

接線端子與二線短接方式依該型號手冊核對。QJ71C24N、其他 C24 變型及不同廠商設備不能只憑 A／B 名稱直接套接。

## 第一輪檢查電源與線路

1. 確認設備供電、模組就緒狀態與接線端子。改線或量電阻前依現場程序停電並確認無外加電壓。

2. 依雙方手冊把訊號極性對上。不同廠商的 A／B 命名可能不同，優先核對正負定義與二線接法。

3. 檢查幹線是否連續、接頭是否鬆脫，先縮短支線並避開大電流與變頻器動力配線。

4. 依線纜與設備手冊檢查終端、偏壓及訊號參考線。屏蔽、保護接地與訊號參考端不可任意當作同一端。

### 終端電阻放在線路兩個物理端點

典型線性總線在兩個端點配置與線纜特性阻抗匹配的終端，常見為 120 Ω；不是每台設備都加一個。QJ71C24N 的阻值請依其手冊選用；既有 Q 系列教學引用的是 110 Ω，不能直接把常見的 120 Ω 當成該模組規格。先查是否已內建或由開關啟用，避免重複加裝。

在斷電、確認其他電路影響已排除的理想情況，兩個 120 Ω 終端並聯約為 60 Ω。這只能作為線索；偏壓與設備內部電路都會影響讀值，不能只看 60 Ω 就宣布接線正確。

### 偏壓與隔離要依設備設計

閒置時的訊號狀態需要可靠，但有些收發器已有失效保護，外加偏壓也會增加負載。先查全線既有配置，不要每一站都隨意加偏壓。若現場地電位差超出介面容許範圍，應查隔離與等電位設計。

參考：[Texas Instruments RS485 Design Guide 拓撲終端與接地](https://www.ti.com/lit/an/slla272d/slla272d.pdf)

## 第二輪確認請求與回覆

| 你看到的證據               | 優先排查                                       |
| -------------------------- | ---------------------------------------------- |
| 主站沒有 TX 活動或送出紀錄 | 觸發條件、忙碌互鎖、通道選擇及通訊程式         |
| 主站有 TX，從站沒有回覆    | 站號、協定、格式、線路極性及設備接收狀態       |
| 線上有回覆，主站仍逾時     | 方向切換、接收長度、CRC、回覆辨識條件與時間    |
| 收到 83H 加例外碼          | 依例外碼處理功能碼、位址或資料，不再當成無回應 |

TX／RX 指示燈只能顯示活動，不能保證資料內容正確。使用隔離且適合現場的擷取工具保存封包；避免同一條線又加入第二個主站同時發問。

### 站號零不適合拿來等讀取回覆

Modbus RTU 的一般從站位址是 1–247。0 是廣播位址，廣播不回覆，不拿它做一般讀取測試。若兩台從站站號相同，它們可能同時回答，造成碰撞。

### 分開看框架間隔與回覆逾時

9600 bps、8E1 每字元共 11 bits，3.5 字元時間約 4.01 ms。這是 RTU 框架分隔的概念，不能直接當成從站處理完成的逾時上限。大於 19200 bps 時，官方串列指南建議固定 t1.5＝750 µs、t3.5＝1.75 ms。

回覆逾時要包含設備處理、傳送與必要的轉向時間。依手冊先設合理有限值，再觀察實測；前一筆完成或逾時後才送下一筆，避免掃描週期每圈都發送。

## 用紀錄把故障縮小到一個條件

1. 選擇手冊已知、允許讀取的單一資料項，保存一次請求。

2. 確認站號、功能碼、封包位址與數量；若工具會自動調整位址，查看實際送出內容。

3. 一次只改一項，例如格式或站號，每次記錄結果。

4. 成功後再逐一加回其他從站與輪詢項目；每加一項就確認錯誤率與更新時間。

| 紀錄欄位        | 填寫內容         |
| --------------- | ---------------- |
| 站號與通訊格式  | ＿＿＿＿＿＿＿＿ |
| 請求 HEX 與時間 | ＿＿＿＿＿＿＿＿ |
| 回覆 HEX 或逾時 | ＿＿＿＿＿＿＿＿ |
| 本次只改了什麼  | ＿＿＿＿＿＿＿＿ |
| 結果與下一步    | ＿＿＿＿＿＿＿＿ |

### 練習與答案

練習一：站號設 0，送讀取請求後一直等待。先改為目標從站的有效單播站號。練習二：回覆是 01 83 02 加有效 CRC。這是 FC03 例外碼 02，先核對位址與範圍，不應記為完全沒有回覆。練習三：只有接回第三台後開始錯誤。優先檢查重複站號、拓撲、終端與新接線段。

### 完成判定

以預先訂定的觀察期間，確認請求都有對應結果、數值可核對、無持續逾時或 CRC 錯誤；拔除測試從站後能顯示失效，接回後能恢復。記錄實際測試次數與錯誤次數，避免只用一次成功就判定完成。

參考：[Modbus 官方 Application Protocol 例外回覆](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)

參考：[Modbus 官方 Serial Line 指南 V1.02](https://www.modbus.org/file/secure/modbusoverserial.pdf)

參考：[Mitsubishi Q 系列序列通訊模組基本手冊 SH080006W](https://dl.mitsubishielectric.com/dl/fa/document/manual/plc/sh080006/sh080006w.pdf)

## 操作完成後的確認與適用範圍

### 完成後應看到什麼結果

以單一主站和單一從站測試時，每筆有效單播請求應有可對應的正常或例外回覆；正常讀取的站號、功能碼及資料長度應符合請求，數值也能與設備狀態核對。只有 TX／RX 燈閃爍還不算完成。

在預先訂定的觀察期間記錄請求次數、成功次數與錯誤次數。中斷測試從站後，主站應在有限時間內顯示逾時或失效；恢復連線後，輪詢應能恢復並更新資料時間。

### 失敗時先查哪裡

1. 沒有送出紀錄：先查觸發條件、忙碌狀態及所選通道。

2. 有送出、線上無回覆：查供電、站號、RTU 協定、格式與線路；依雙方手冊核對極性及二線接法。

3. 線上有回覆但程式不接受：查方向切換、CRC、接收長度與逾時；若已有例外碼，轉查功能碼、位址與範圍。

### 適用型號與限制

本篇以 Q06UDVCPU 搭配 QJ71C24N 的 CH2 RS422／485 介面為既有教材背景。一般 Modbus RTU 的排查順序也適用其他主站與從站；端子、短接、終端及隔離方式須逐一核對實際型號。

不要把 QJ71C24N 的接線直接套到 QJ71C24N-R2、QJ71C24N-R4 或其他廠牌。本文不提供通用端子對接表，也不適用 Modbus TCP 的實體網路排查。無從站型號時，9600 bps、8E1 與站號 1 只是示例，不能當成設備出廠值。
