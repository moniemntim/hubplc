## 先重現一個數字：1.151 秒，為什麼表上要到 1.2 秒？

上方模型預設由 20 升到 80 EU（工程單位），時間常數 τ=0.5 秒、固定延遲=0、取樣間隔=0.1 秒。這是合成的一階響應，不是從實機擬合出的特性。

1. 點「重設範例」，看 90% 那列：門檻是 `20 + (80−20)×0.9 = 74 EU`。
2. 理論跨越時間約為 1.1512925465 秒；取樣只在 0、0.1、0.2…秒，因此首次取到已跨越的值是在 1.2 秒。
3. 該筆約為 74.5569 EU。不能把首次觀察時間 1.2 秒寫成理論精確跨越，也不能拿顯示畫面的刷新時間代替來源取樣時間。
4. 把固定延遲改為 0.3 秒。含延遲的理論跨越改為約 1.4512925465 秒，首次取樣跨越為 1.5 秒；不含延遲的 T90 仍為約 1.1513 秒。
5. 點「切換為下降階躍」。初值改成 80、終值20，90%變化門檻是26 EU，時間相同。下降時找的是讀值降到門檻以下，不能一直使用向上的比較。
6. 將 τ 清空或填0，結果應撤下並顯示錯誤。重設後再繼續。

頁面限定 τ 和取樣間隔 0.001–1000 秒、固定延遲 0–1000 秒。這些是試算輸入範圍，不是設備適用規格；取樣格點固定從 t=0 開始，實際採集的相位可能不同。

## 三個時間，不能用同一名稱

一階模型在固定延遲 L 之前維持初值，之後為 `y(t)=y0+(yfinal−y0)×[1−exp(−(t−L)/τ)]`。將變化比例設為 p，理論跨越時間為 `t(p)=L−τ×ln(1−p)`。

| 指標       | 本課定義                        | τ=0.5 秒、L=0          |
| ---------- | ------------------------------- | ---------------------- |
| 時間常數 τ | 到達 1−exp(−1)，約63.212%的變化 | 0.5 秒，約57.9272 EU   |
| T90        | 從延遲結束起，到90%的時間       | ln(10)×τ，約1.151293秒 |
| T10–90     | 10%跨越至90%跨越的間隔          | ln(9)×τ，約1.098612秒  |

本頁摘要刻意把不含延遲的 T90 與含延遲的表格時間分開。若專案把 T90 定義為從實際輸入施加起算，報告應將 L 包含進去並寫明，不能只交一個沒有起點的數字。

[MathWorks stepinfo 文件](https://www.mathworks.com/help/control/ref/dynamicsystem.stepinfo.html) 的預設 RiseTime 使用10%到90%，SettlingTime則依誤差帶與持續留在帶內的條件計算；本頁用解析一階公式，沒有呼叫 MATLAB，也沒有實作完整 stepinfo 演算法。

## 實際量測表應該填什麼？

先依設備與現場程序安排受控測試，記錄真實輸入何時改變，不把操作命令送出時間假裝成物理階躍時間。階躍幅度、速度與範圍須符合裝置條件，不能在未知運轉設備上任意施加。

| 紀錄         | 要填的內容                               | 缺少時不能宣稱什麼               |
| ------------ | ---------------------------------------- | -------------------------------- |
| 實際輸入     | 初值、終值、變化過程及輸入事件時間       | 不能分離來源切換與感測器響應     |
| 輸出原始序列 | 每點時間、值、來源品質、序號             | 不能只憑最終值估T90              |
| 採集條件     | 取樣間隔、時間戳位置、同步方式、濾波窗口 | 不能把通訊或平均延遲全算給感測器 |
| 判定條件     | y0、yfinal、門檻、穩定帶、停留時間       | 不同定義的結果不能直接比較       |
| 測試版本     | 型號、安裝方式、環境、設定與重複次數     | 無法判斷下次變化來自設備還是方法 |

本例若最後一筆低於74、下一筆已達74，且單調、無缺樣與雜訊，可把跨越定位在這兩筆之間。採用100 ms資料，沒有額外模型證據就不能宣稱微秒級實測精度。若另用插值估時間，保留原始兩點，並把插值結果標成估計。

真實資料若先超過再回落，首次跨越只代表曾到達。若有缺樣、Bad品質或最後仍未穩定，不拿最後一筆硬當 yfinal；標示該次無法完成判讀，保留原因與原始序列。

## 為什麼已到90%，還不能說穩定？

假設本例的穩定帶約定為最終值±階躍幅度的2%，則上升20→80時為 `80 ± 1.2 EU`，即78.8至81.2。90%門檻74尚未進入此帶，兩者是不同事件。

即使某一點進帶，也須滿足事先約定的連續停留時間或連續樣本條件。遇到超調與振盪，要保留峰值、最後離帶及回到帶內的時刻。本頁的一階模型必定單調，所以它不能示範真實超調、證明硬體穩定，或替代含雜訊的驗收演算法。

若測得較慢，先比較輸入源、時間基準、取樣間隔和濾波設定，再檢查感測器。單憑通過63.2%一點不能證明設備是一階系統；明顯超調或多段動態更不能硬套一個 τ。

## 交付一份能被重算的結果

至少分開上升與下降結果，每次保存原始序列、有效性、門檻與跨越相鄰點；重複次數依程序規定，呈現各次結果和散布，不只留平均。標示報告的是感測器輸出、PLC接收還是HMI顯示這一段。

若縮短或改變濾波窗口，重新記錄版本與條件；先看[濾波與尖峰重播](/articles/filtered-peaks-raw-data-traceability)，確認不是計算方式改變了表觀響應。換件後的靜態與動態驗收則見[感測器更換檢查](/articles/sensor-replacement-compatibility-calibration-check)。
