# 內容整改驗收方式

本次整改保留「逐篇實質審查」的全站範圍，改用讀者能完成的工作衡量成果。既有reviewed-local只表示當時來源與案例核對，不保證符合本次PLC實用性標準或AdSense核准。

1. 每篇先說讀者要解決的具體問題，提供可操作步驟與結果判讀；不能以字數、附件數或測試數代替用途。
2. 基礎邏輯優先頁面直接操作，下載CLI是進階選項；不把安装Node.js當PLC初學者必要前置。
3. 平台教學需有適用產品/版本、完整程式、變數/裝置對照及驗收順序。未編譯、未模擬、未實測分別標記，沒有證據不寫成功。
4. 題目重疊先逐篇比較目的與內容，再整合正文與內部連結；需要移除網址時處理相容與導向，不按標題批量刪文。
5. 工具頁需能直接輸入、顯示結果與限制；原創價值在任務完成，不在換句話說官方手冊。
6. 每次上線核對內容、互動、可及性、手機排版與下載；作者/來源/回報管道保持真實，不編造經驗、流量或使用者反馈。

本輪交付：首頁代表教學、文章入口起步路徑、故障復歸頁面互動與ST對照。ST沒有編譯/runtime證據，這項仍待驗證；沒有申請重新送審。其餘文章仍依inventory逐篇處理。
