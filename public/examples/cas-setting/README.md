# Local SQLite conditional-setting example

Node.js 24.19.0. Real local SQLite via node:sqlite; no network, login, HMI or PLC. Fixed resource TEMP_SP, raw integer 0..1000 (raw/10 Celsius), version7/raw500/epoch1 initially. A/B are trusted scenario actors, not authentication.

CAS article: save store.mjs, demo.mjs, race.mjs, race-worker.mjs, self-test.mjs and this README together. Run `node self-test.mjs` and `node demo.mjs`.

HMI article: save store.mjs, editor.mjs, hmi-demo.mjs, self-test.mjs and this README together. Run `node self-test.mjs` and `node hmi-demo.mjs`. Both download sets can coexist.

Each invocation creates new hubplc-cas-* directories in the OS temporary directory and leaves its SQLite files for inspection. Existing paths are never initialized again. No automatic cleanup or production-file access. The race worker is started by race.mjs; do not invoke it by hand.

submit(actor, {id,expectedVersion,raw,epoch}) accepts exactly those four own fields. ID is 1..40 uppercase ASCII letters/digits/hyphens. Version and epoch are safe integers 1..2147483647. raw must be a safe integer 0..1000. Unknown actors and invalid requests have no ledger entry. Maximum 1000 operation records; full ledger refuses new IDs without deleting history. Exact replays still work.

BEGIN IMMEDIATE encompasses result lookup, conditional UPDATE, result INSERT and COMMIT. Ledger INSERT failure rolls back the setting too. UPDATE includes both expected resource version and authority epoch. All validated results, including conflicts and fencing, are recorded; identical ID+actor+version+value+epoch returns the historical result without a new write. Changed content under the same ID is rejected. A replay/query result's current field is historical; call read() for the current setting. rotateEpoch(expected) is one conditional UPDATE, a test administration action, not leader election. Arbitrary SQL writers and external PLC writers are outside this boundary.

race.mjs starts two Node child processes against one database; both read v7, report ready, then receive go. It asserts one commit, one version conflict and final v8, not which actor wins or literal simultaneous execution. SQLite busy_timeout=5000; unresolved locking/filesystem errors throw, not silently become conflicts. No load/performance guarantees.

editor.mjs preserves baseline/current/draft independently. Conflict requires explicit rebaseKeepingDraft() or discardDraft() before a new intent. A lost reply is synthetic: the DB operation ran but its returned data is discarded. unknown permits only queryOriginal(), not edit/new submission/rebase/discard; NOT_FOUND stays unknown. A thrown store error also leaves unknown. No automatic retry, manual resolution, persistent editor state or crash recovery is provided.

Database committed_at is generated by SQL wall time during UPDATE, not PLC applied time or exact COMMIT completion. It is not used to order competing requests. All results have deviceStatus=NOT_CONNECTED. This example does not prove distributed fencing, safe backup restore, power-loss recovery, hardware exactly-once effects or tamper-proof auditing.

Optional practice.mjs lets you change firstRaw/secondRaw/secondExpectedVersion and inspect CAS results without changing demo assertions. practice-editor.mjs lets you change myDraftRaw and prints conflict, explicit rebase and final editor state. Its sequential rebase line represents an explicit user decision, not an automatic UI retry policy. Both run as normal Node files and create fresh temporary databases.

query(actor,id) reads a historical record. For resolving an unknown intent, query(actor,id,expectedRequest) also compares the full original version/raw/epoch content. editor.queryOriginal() always supplies this binding, so a reused ID cannot turn an older successful write into proof of the new intent.
